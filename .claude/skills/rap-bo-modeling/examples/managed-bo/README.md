# Minimal Managed RAP BO — Customer

A complete scaffold for the smallest useful managed BO. Adapt for your domain.

## Files

```
zcustomer.tabl                    DB table (DDIC)
Z_I_Customer.ddls                 Interface CDS
Z_C_Customer.ddls                 Composite CDS (acts as root for the BO)
Z_C_Customer.bdef                 Base behavior definition
zbp_z_c_customer.clas             Behavior implementation pool
Z_C_Customer_Projection.ddls      Consumption projection
Z_C_Customer_Projection.bdef      Projection BDEF
Z_CUSTOMER_SD.srvd                Service definition
Z_CUSTOMER_SB.srvb                Service binding
ZCUST_MSG (T100 message class)    For error messages
```

## DB Table — `zcustomer`

```
Field           Type              Length   Description
=====           ====              ======   ===========
CLIENT          MANDT             3        Client (key)
CUSTOMER_ID     CHAR              10       Customer ID (key)
NAME            CHAR              80       Name
CITY            CHAR              40       City
COUNTRY         LAND1             3        Country
BLOCKED         BOOLE_D           1        Blocked flag
CREATED_AT      ABP_CREATION_TSTMPL         Created at
CREATED_BY      ABP_CREATION_USER 12       Created by
LAST_CHANGED_AT ABP_LASTCHANGE_TSTMPL       Last changed at
LAST_CHANGED_BY ABP_LASTCHANGE_USER 12     Last changed by
LOCAL_LAST_CHANGED_AT ABP_LOCINST_LASTCHANGE_TSTMPL Local last changed (for draft etag)
```

Also a draft mirror `zcustomer_d` — autogenerated when you activate the BO with draft.

## `Z_I_Customer.ddls` — Interface CDS

```sql
@AbapCatalog.viewEnhancementCategory: [#NONE]
@AccessControl.authorizationCheck:    #CHECK
@EndUserText.label:                   'Customer — Interface'
@Metadata.allowExtensions:            true
@VDM.viewType:                        #BASIC
@ObjectModel.usageType:               { dataClass: #MASTER, serviceQuality: #A, sizeCategory: #M }

define view entity Z_I_Customer
  as select from zcustomer as Customer
{
  key Customer.customer_id    as CustomerId,
      Customer.name           as Name,
      Customer.city           as City,
      Customer.country        as Country,
      Customer.blocked        as Blocked,
      @Semantics.systemDateTime.createdAt: true
      Customer.created_at     as CreatedAt,
      @Semantics.user.createdBy: true
      Customer.created_by     as CreatedBy,
      @Semantics.systemDateTime.lastChangedAt: true
      Customer.last_changed_at as LastChangedAt,
      @Semantics.user.lastChangedBy: true
      Customer.last_changed_by as LastChangedBy,
      @Semantics.systemDateTime.localInstanceLastChangedAt: true
      Customer.local_last_changed_at as LocalLastChangedAt
}
```

## `Z_C_Customer.ddls` — Composite (root for BO)

```sql
@AccessControl.authorizationCheck: #CHECK
@EndUserText.label:                'Customer — Composite'
@VDM.viewType:                     #COMPOSITE
@ObjectModel.semanticKey:          [ 'CustomerId' ]

define root view entity Z_C_Customer
  as projection on Z_I_Customer
{
  key CustomerId,
      Name,
      City,
      Country,
      Blocked,
      CreatedAt,
      CreatedBy,
      LastChangedAt,
      LastChangedBy,
      LocalLastChangedAt
}
```

`define root view entity` — root of a BO tree. (Single-entity BO here; for parent-child you'd add child entities and associations.)

## `Z_C_Customer.bdef` — Base BDEF

```
managed implementation in class zbp_z_c_customer unique;
strict ( 2 );
with draft;

define behavior for Z_C_Customer alias Customer
persistent table zcustomer
draft table zcustomer_d
lock master total etag LastChangedAt
authorization master ( instance )
etag master LocalLastChangedAt
{
  field ( readonly )            CreatedAt, CreatedBy, LastChangedAt, LastChangedBy, LocalLastChangedAt;
  field ( mandatory )           Name, Country;
  // External numbering: the consumer supplies the CHAR key on create; the key is frozen afterwards.
  // (field ( numbering : managed ) would require a 16-character byte-like UUID key instead of CHAR 10.)
  field ( mandatory : create, readonly : update ) CustomerId;

  create;
  update;
  delete;

  draft action Edit;
  draft action Activate optimized;
  draft action Discard;
  draft action Resume;
  draft determine action Prepare { validation validate_name; }

  validation validate_name on save { create; update; }
  determination set_audit_fields on save { create; update; }

  action ( features : instance ) block result [1] $self;

  mapping for zcustomer
  {
    CustomerId         = customer_id;
    Name               = name;
    City               = city;
    Country            = country;
    Blocked            = blocked;
    CreatedAt          = created_at;
    CreatedBy          = created_by;
    LastChangedAt      = last_changed_at;
    LastChangedBy      = last_changed_by;
    LocalLastChangedAt = local_last_changed_at;
  }
}
```

## `zbp_z_c_customer` — Behavior pool

```abap
CLASS lhc_customer DEFINITION INHERITING FROM cl_abap_behavior_handler.

  PRIVATE SECTION.
    METHODS:
      validate_name FOR VALIDATE ON SAVE
        IMPORTING keys FOR Customer~validate_name,

      set_audit_fields FOR DETERMINE ON SAVE
        IMPORTING keys FOR Customer~set_audit_fields,

      block FOR MODIFY
        IMPORTING keys FOR ACTION Customer~block RESULT result,

      get_instance_authorizations FOR INSTANCE AUTHORIZATION
        IMPORTING keys REQUEST requested_authorizations FOR Customer RESULT result.

ENDCLASS.

CLASS lhc_customer IMPLEMENTATION.

  METHOD validate_name.
    READ ENTITIES OF Z_C_Customer IN LOCAL MODE
      ENTITY Customer
      FIELDS ( CustomerId Name )
      WITH CORRESPONDING #( keys )
      RESULT DATA(lt_customers).

    LOOP AT lt_customers ASSIGNING FIELD-SYMBOL(<fs_customer>).
      IF <fs_customer>-Name IS INITIAL OR strlen( <fs_customer>-Name ) < 3.
        APPEND VALUE #( %tky = <fs_customer>-%tky ) TO failed-customer.
        APPEND VALUE #( %tky               = <fs_customer>-%tky
                        %msg               = new_message(
                                                id       = 'ZCUST_MSG'
                                                number   = '001'
                                                severity = if_abap_behv_message=>severity-error
                                                v1       = <fs_customer>-Name )
                        %element-Name      = if_abap_behv=>mk-on )
          TO reported-customer.
      ENDIF.
    ENDLOOP.
  ENDMETHOD.

  METHOD set_audit_fields.
    READ ENTITIES OF Z_C_Customer IN LOCAL MODE
      ENTITY Customer
      FIELDS ( CustomerId ) WITH CORRESPONDING #( keys )
      RESULT DATA(lt_customers).

    DATA(lv_change_timestamp) = cl_abap_tstmp=>utclong2tstmp( utclong_current( ) ).
    DATA(lv_user)             = cl_abap_context_info=>get_user_technical_name( ).

    MODIFY ENTITIES OF Z_C_Customer IN LOCAL MODE
      ENTITY Customer
      UPDATE FIELDS ( LastChangedAt LastChangedBy LocalLastChangedAt )
      WITH VALUE #( FOR <fs_customer> IN lt_customers
                    ( %tky               = <fs_customer>-%tky
                      LastChangedAt      = lv_change_timestamp
                      LastChangedBy      = lv_user
                      LocalLastChangedAt = lv_change_timestamp ) )
      REPORTED DATA(lt_update_reported).
  ENDMETHOD.

  METHOD block.
    MODIFY ENTITIES OF Z_C_Customer IN LOCAL MODE
      ENTITY Customer
      UPDATE FIELDS ( Blocked )
      WITH VALUE #( FOR ls_key IN keys ( %tky = ls_key-%tky Blocked = abap_true ) )
      FAILED   DATA(lt_failed_modify)
      REPORTED DATA(lt_reported_modify).

    READ ENTITIES OF Z_C_Customer IN LOCAL MODE
      ENTITY Customer ALL FIELDS WITH CORRESPONDING #( keys )
      RESULT DATA(lt_blocked).

    result = VALUE #( FOR <fs_blocked_customer> IN lt_blocked
                      ( %tky = <fs_blocked_customer>-%tky %param = <fs_blocked_customer> ) ).
  ENDMETHOD.

  METHOD get_instance_authorizations.
    " example: only allow block to users with auth object ZCUST_ADM
    LOOP AT keys INTO DATA(ls_key).
      DATA lv_auth_block TYPE abp_behv_auth.
      AUTHORITY-CHECK OBJECT 'ZCUST_ADM' ID 'ACTVT' FIELD '02'.
      lv_auth_block = COND #( WHEN sy-subrc = 0
                           THEN if_abap_behv=>auth-allowed
                           ELSE if_abap_behv=>auth-unauthorized ).

      APPEND VALUE #( %tky      = ls_key-%tky
                      %action-block = lv_auth_block )
        TO result.
    ENDLOOP.
  ENDMETHOD.

ENDCLASS.
```

## `Z_C_Customer_Projection.ddls` — Projection

```sql
@AccessControl.authorizationCheck: #CHECK
@EndUserText.label:                'Customer — Fiori projection'
@Metadata.allowExtensions:         true
@Search.searchable:                true
@ObjectModel.semanticKey:          [ 'CustomerId' ]
@UI.headerInfo: { typeName: 'Customer', typeNamePlural: 'Customers',
                  title: { value: 'Name' } }

define root view entity Z_C_Customer_Projection
  provider contract transactional_query
  as projection on Z_C_Customer as Customer
{
  @UI.lineItem: [ { position: 10, label: 'Customer ID' } ]
  @UI.identification: [ { position: 10 } ]
  @Search.defaultSearchElement: true
  key Customer.CustomerId,

  @UI.lineItem: [ { position: 20, label: 'Name' } ]
  @UI.identification: [ { position: 20 } ]
  @Search.defaultSearchElement: true
  Customer.Name,

  @UI.lineItem: [ { position: 30, label: 'City' } ]
  Customer.City,

  @UI.lineItem: [ { position: 40, label: 'Country' } ]
  Customer.Country,

  @UI.lineItem: [ { position: 50, label: 'Blocked',
                    criticality: 'Blocked' } ]

  @UI.hidden: true

  @UI.hidden: true
```

## Service Definition

```
@EndUserText.label: 'Customer service'
define service Z_CUSTOMER_SD {
  expose Z_C_Customer_Projection as Customer;
}
```

## Service Binding

In ADT: New → Service Binding → name `Z_CUSTOMER_SB`, target `Z_CUSTOMER_SD`, binding type "OData V4 — UI", activate.

The "Service URL" preview now serves the BO via OData. Drop the URL into a Fiori app or hit `/sap/opu/odata4/sap/z_customer_sb/srvd_a2x/sap/z_customer_sd/0001/Customer` to test.

## Wiring Fiori (briefly)

- Create a Fiori Elements List Report Object Page app pointing at the service.
- The annotations in the projection (`@UI.*`) drive the UI — list columns, object page sections, search.
- Adobe Forms, value helps, and side effects can be added via further annotations.

## Test snippet (sketch — see abap-unit-tdd skill for the full TDD pattern)

```abap
CLASS ltcl_customer_create DEFINITION FOR TESTING DURATION SHORT RISK LEVEL HARMLESS.
  PRIVATE SECTION.
    METHODS create_with_short_name_fails FOR TESTING.
ENDCLASS.

CLASS ltcl_customer_create IMPLEMENTATION.
  METHOD create_with_short_name_fails.
    DATA(lo_env) = cl_cds_test_environment=>create_for_multiple_cds(
                  i_for_entities = VALUE #( ( name = 'Z_C_CUSTOMER' ) ) ).

    " arrange — clear table, set test fixtures …

    MODIFY ENTITIES OF Z_C_Customer
      ENTITY Customer
      CREATE FIELDS ( CustomerId Name City Country )
      WITH VALUE #( ( %cid = 'C1' CustomerId = '0000000042'
                      Name = 'AB' City = 'X' Country = 'DE' ) )
      MAPPED DATA(lt_mapped).

    " validate_name is a BDEF `validation … on save`, so failed/reported are
    " only populated once the save sequence runs — commit before asserting.
    COMMIT ENTITIES RESPONSE OF Z_C_Customer
      FAILED   DATA(lt_failed_commit)
      REPORTED DATA(lt_reported_commit).

    cl_abap_unit_assert=>assert_not_initial(
      act = lt_failed_commit-customer
      msg = 'Expected create with 2-char name to fail the on-save validation' ).

    lo_env->destroy( ).
  ENDMETHOD.
ENDCLASS.
```
